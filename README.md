# Кто приходил на кофе

Календарь-хитмап посещений в стиле гитхабовской истории коммитов.
Ноль зависимостей: нужен только Node 18+.

## Запуск

```bash
node server.js
```

Открыть http://localhost:3000

Переменные окружения:

| Переменная  | По умолчанию   | Что делает            |
|-------------|----------------|-----------------------|
| `PORT`      | `3000`         | порт                  |
| `DATA_FILE` | `./data.json`  | путь к файлу с данными |

## Деплой на Linux

Нужен только Docker с плагином compose. Из папки проекта:

```bash
docker compose up -d --build
```

Открыть `http://<адрес-сервера>:3000`. Порт меняется на лету:

```bash
PORT=8080 docker compose up -d --build
```

| Команда                     | Что делает                          |
|-----------------------------|-------------------------------------|
| `docker compose logs -f`    | смотреть логи                       |
| `docker compose restart`    | перезапустить                       |
| `docker compose down`       | остановить (данные остаются)        |
| `docker compose down -v`    | остановить и **стереть данные**     |
| `docker compose up -d --build` | выкатить новую версию кода       |

### Где живут данные

В именованном томе `coffee-data`, смонтированном в `/data`. Контейнер можно
удалять и пересоздавать сколько угодно — `data.json` переживёт.

Том обязателен: `persist()` пишет во временный файл и делает `rename`, а он не
работает между разными файловыми системами. Поэтому монтируется **папка**
`/data`, а не отдельный файл — при монтировании файла `rename` снёс бы точку
монтирования.

Бэкап и восстановление:

```bash
docker compose cp coffee:/data/data.json ./backup.json
docker compose cp ./backup.json coffee:/data/data.json && docker compose restart
```

Восстановление требует перезапуска: сервер читает файл только на старте.

### Список имён без пересборки

`public/names.js` смонтирован в контейнер только на чтение. Поправили файл на
сервере — обновили страницу, пересобирать образ не нужно.

Если разворачиваете не из репозитория и файла рядом нет, уберите эту строку из
`docker-compose.yml`: Docker создаст на месте отсутствующего файла пустую
папку, и список имён пропадёт.

### Что внутри

Образ — `node:22-alpine` без единой зависимости, запуск от пользователя
`node`, не от root. `init: true` поднимает tini первым процессом, чтобы
`SIGTERM` доходил до сервера. Сервер его ловит: дописывает начатое и выходит с
кодом 0, так что остановка не теряет последнюю отметку. Healthcheck дёргает
`/api/log` раз в 30 секунд, `restart: unless-stopped` поднимает контейнер после
перезагрузки машины.

Аутентификации по-прежнему нет — наружу без реверс-прокси с паролем выставлять
не стоит.

## Структура

```

Dockerfile         образ для деплоя
docker-compose.yml запуск одной командой, том с данными
public/index.html  разметка
public/styles.css  стили
public/names.js    СПИСОК ИМЁН для выпадающего списка — правится руками
public/app.js      сетка, выбор дня, запросы к API
data.json          данные, создаётся при первом запуске
```

## Список имён

Имена отмечаются галочками — можно выбрать сразу нескольких и сохранить их
одной кнопкой. Сам список лежит в `public/names.js`
в массиве `window.ROSTER` — это единственное место, которое нужно править:

```js
window.ROSTER = [
  "Аня",
  "Борис",
  "Вера",
];
```

Файл отдаётся как обычная статика, сервер его не читает и не проверяет.
После правки достаточно обновить страницу — перезапускать `node server.js`
не нужно.

К списку автоматически добавляются те, кого отмечали раньше, но в `ROSTER`
уже нет: иначе их нельзя было бы отметить снова. Имена сортируются по
алфавиту, так что порядок строк в файле роли не играет. Уже отмеченные в
выбранный день из списка убираются; когда не осталось никого — вместо списка
появляется «Все уже отмечены». Кнопка неактивна, пока не стоит ни одной
галочки, и показывает их число, когда выбрано больше одного человека.

Галочки сбрасываются при переключении дня и после успешного сохранения. Если
сервер ответил ошибкой, выбор остаётся — можно нажать ещё раз.

## Обязательные участники

В `public/names.js` рядом с ростером лежит `window.REQUIRED` — «отцы-кафахлёбы».
Если после сохранения в дне не окажется никого из них, запрос не уходит вовсе,
а под кнопкой «Отметить» появляется предупреждение из `window.REQUIRED_NOTE`:

```js
window.REQUIRED = ["Миша", "Кирилл"];
window.REQUIRED_NOTE = "Кафа без отцов-основателей кафахлёбства не засчитывается";
```

Достаточно одного любого из списка. Пустой массив выключает проверку.

Проверяется состав дня целиком, а не только новые галочки: если «отец» уже
отмечен в этом дне раньше, добавлять к нему остальных можно свободно — иначе
после первого сохранения день оказался бы заперт.

Имена из `REQUIRED` всегда попадают в список галочек, даже если их нет в
`ROSTER`, — иначе выбрать их было бы нечем и день нельзя было бы засчитать.

Предупреждение исчезает, как только тронули любую галочку, сменили день или
сохранение прошло. Верхний баннер остаётся под ошибки сервера — правила учёта
и сетевые сбои не смешиваются.

Проверка живёт на клиенте: это правило учёта, а не безопасность. Прямой запрос
к API её не увидит.

## API

| Метод    | Путь                                | Что делает                  |
|----------|-------------------------------------|-----------------------------|
| `GET`    | `/api/log`                          | всё состояние               |
| `POST`   | `/api/days/:date/attendees`         | отметить, тело `{"name":"…"}` или `{"names":["…"]}` |
| `DELETE` | `/api/days/:date/attendees/:name`   | убрать из дня               |
| `DELETE` | `/api/people/:name`                 | убрать человека изо всех дней |

Дата — `ГГГГ-ММ-ДД`. Имена в URL нужно кодировать (`encodeURIComponent`).
Группа уходит одним запросом: `{"names":[…]}` принимает до 50 имён, схлопывает
дубли внутри списка и делает одну запись на диск. Пустой список — ошибка 400.
Любой изменяющий запрос возвращает новое состояние целиком, так что клиенту
не нужен отдельный `GET` после записи.

## Хранилище

Всё состояние живёт в памяти процесса и сбрасывается в `data.json` после
каждого изменения. Запись идёт во временный файл с последующим `rename`, так что
падение посреди записи не оставит обрезанный JSON. Записи выстроены в цепочку
промисов — параллельные запросы не перетирают друг друга.

Бэкап — обычная копия `data.json`. Правка руками тоже работает, но сервер
надо перезапустить: он читает файл только на старте.

## Что стоит знать

- Аутентификации нет. Кто открыл страницу — тот и правит. Для офисной сети
  нормально, наружу выставлять не стоит.
- Открытые вкладки опрашивают сервер раз в 15 секунд, поэтому чужие отметки
  подтягиваются сами.
- Цвет считается относительно максимума по всем дням, а не по фиксированной
  шкале: календарь выглядит одинаково живым и для троих, и для тридцати человек.
- Сетка показывает последний 371 день и всегда заканчивается сегодняшним днём.
- Имена сравниваются без учёта регистра, пробелы схлопываются: `" аня "` и
  `"АНЯ"` — один человек.
