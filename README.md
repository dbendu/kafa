# Кто приходил на кофе

Календарь-хитмап посещений в стиле гитхабовской истории коммитов.
Внизу три рейтинга: кто ходит чаще, кто чаще кидает и кто чаще косячит.
Ноль зависимостей: нужен только Node 22.13+ (встроенный модуль SQLite).

## Запуск

```bash
node server.js
```

Рядом с `server.js` должна лежать существующая `data.sqlite`. При неверном пути сервер завершится с ошибкой, не создавая пустую базу.

Открыть http://localhost:3000

Переменные окружения:

| Переменная  | По умолчанию   | Что делает            |
|-------------|----------------|-----------------------|
| `PORT`      | `3000`         | порт                  |
| `DATA_FILE` | `./data.sqlite`  | путь к файлу с данными |

## Деплой на Linux

Нужен Docker с плагином compose и домен, A-запись которого указывает на этот
сервер. Порядок:

```bash
# 1. настройки конкретного сервера — их нет в репозитории
cp .env.example .env   # вписать домен, логин и пароль

# 2. загрузите актуальную data.sqlite в каталог проекта на сервере
# 3. подготовьте контейнер и положите базу в его том
docker compose build coffee
docker compose create coffee
docker compose cp ./data.sqlite coffee:/data/data.sqlite
docker compose run --rm --no-deps --user root coffee chown node:node /data/data.sqlite
# 4. запустите приложение
docker compose up -d
```

`.env` не лежит в репозитории: там пароль открытым текстом. Без него compose
откажется стартовать с понятной ошибкой.

Через полминуты `https://example.com` открывает приложение. Сертификат Caddy
получает сам и продлевает без напоминаний; `http://` и `www.` уводятся на него
редиректом.

### Что должно быть готово до запуска

- `A`-запись домена (и `www`, если нужен) указывает на IP сервера
- порты **80 и 443** открыты в файрволе; 80 нужен и дальше — по нему идёт
  проверка Let's Encrypt при продлении
- на 80/443 больше никто не висит: `ss -lntp | grep -E ':(80|443)'`.
  Если там nginx или apache — остановите, иначе контейнер Caddy не стартует

Само приложение наружу не смотрит: порт 3000 доступен только Caddy по
внутренней сети compose. Постучаться в него можно изнутри:

```bash
docker compose exec coffee wget -qO- localhost:3000/api/log
```

| Команда                     | Что делает                          |
|-----------------------------|-------------------------------------|
| `docker compose logs -f`    | смотреть логи                       |
| `docker compose restart`    | перезапустить                       |
| `docker compose down`       | остановить (данные остаются)        |
| `docker compose down -v`    | остановить и **стереть данные**     |
| `docker compose up -d --build` | выкатить новую версию кода       |
| `docker compose logs -f caddy` | смотреть, что с сертификатом     |

### Где живут данные

Рабочая база — `/data/data.sqlite` в именованном томе `coffee-data`.
Контейнер запускает сервер напрямую и использует готовую базу из тома.
При пересоздании контейнера данные сохраняются. Файл рядом с Compose
не подключается к контейнеру: его нужно один раз скопировать командами выше.

Для замены базы на уже работающем сервере сначала остановите приложение
и сохраните резервную копию текущего файла. Затем загрузите актуальную
`data.sqlite` в каталог проекта на сервере и выполните:

```bash
docker compose stop coffee
docker compose cp coffee:/data/data.sqlite ./backup.sqlite
docker compose cp ./data.sqlite coffee:/data/data.sqlite
docker compose run --rm --no-deps --user root coffee chown node:node /data/data.sqlite
docker compose up -d --build
```

Перед отправкой файла сохраните изменения и закройте базу в редакторе.

Бэкап при остановленном приложении:

```bash
docker compose stop coffee
docker compose cp coffee:/data/data.sqlite ./backup.sqlite
docker compose start coffee
```

Восстановление:

```bash
docker compose stop coffee
docker compose cp ./backup.sqlite coffee:/data/data.sqlite
docker compose run --rm --no-deps --user root coffee chown node:node /data/data.sqlite
docker compose start coffee
```

### Пароль

Смотреть историю может кто угодно. Отмечать приходы и кидки и убирать из дня —
только по логину и паролю.

Задаются в `.env`:

```
AUTH_USER=kafa
AUTH_PASS=придумайте-пароль
```

Применить:

```bash
docker compose up -d
```

Проверку делает сам сервер: всё, кроме `GET`, требует заголовка `X-Auth`.
Сравнение обычное, посимвольное, без хешей — это счётчик кофе, а не банк.

Пароль лежит на сервере открытым текстом в `.env`, поэтому файл не попадает в
репозиторий (см. `.gitignore`). Шаблон рядом — `.env.example`. Если оставить
`AUTH_USER` и `AUTH_PASS` пустыми, проверки не будет вовсе и править сможет
кто угодно; при старте сервер пишет об этом в лог.

Пароль можно писать кириллицей — в заголовок он уходит закодированным.

**Как это выглядит для людей.** Под списком участников есть ссылка «Войти,
чтобы отмечать». Логин с паролем вводятся один раз и запоминаются в браузере до
нажатия «выйти». Если попробовать отметить без входа, форма откроется сама.

### Корона у «отцов»

Имена из `window.REQUIRED` показываются с картинкой `public/crown.webp` —
в строках участников и рейтинге. Остальные без неё.

Картинка зашита в образ, так что после замены нужна пересборка:
`docker compose up -d --build`.

### Ранги в списке «кто ходит чаще»

Ранг — место по числу приходов. У кого приходов поровну, у тех и ранг общий:
приходы 4, 3, 2, 1, 1 дают ранги 1, 2, 3, 4, 4.

В рейтинге приходов видны все имена из списка, в том числе те, кто ещё ни разу
не приходил: у них ноль, пустая полоска и никакой картинки. В рейтинге кидков
наоборот — кто не кидал, того там нет вовсе.

Картинки задаются в `public/names.js`, первая строка — 1 ранг:

```js
window.RANKS = [
  "/ranks/1.webp",
  "/ranks/36.webp",
  "/ranks/3.webp",
  "/ranks/11.webp",
];
```

Файлы лежат в `public/ranks/`, у кидков — в `public/antiranks/`. Добавить ранг —
положить туда картинку и дописать строку. Кому ранга не хватило, тот идёт без
картинки.

Папка монтируется с хоста, как и `names.js`, — менять картинки и список можно
без пересборки, достаточно обновить страницу.

Размер под интерфейс — 64 пикселя по высоте, показываются в 20.

Такой же список есть у рейтинга кидков — `window.ANTIRANKS`, см. «Кидки».

### Список имён без пересборки

`public/names.js` смонтирован в контейнер только на чтение. Поправили файл на
сервере — обновили страницу, пересобирать образ не нужно.

Если разворачиваете не из репозитория и файла рядом нет, уберите эту строку из
`docker-compose.yml`: Docker создаст на месте отсутствующего файла пустую
папку, и список имён пропадёт.

### Что внутри

Два контейнера. `coffee` — само приложение: `node:22-alpine` без единой
зависимости, запуск от пользователя `node`, не от root. `init: true` поднимает
tini первым процессом, чтобы `SIGTERM` доходил до сервера. Сервер его ловит:
дописывает начатое и выходит с кодом 0, так что остановка не теряет последнюю
отметку. Healthcheck дёргает `/api/log` раз в 30 секунд,
`restart: unless-stopped` поднимает контейнеры после перезагрузки машины.

`caddy` — реверс-прокси на 80/443: TLS, сжатие, редиректы. Сертификаты лежат в
томе `caddy-data`. Том важен: без него каждый пересозданный контейнер просит
сертификат заново и упирается в недельные лимиты Let's Encrypt.

### Смена домена

Поправить `DOMAIN` в `.env` и перезапустить прокси:

```bash
docker compose up -d caddy
```

Старый сертификат останется в томе, новый Caddy закажет сам.

## Список имён

У каждого человека счётчик посещений: кнопка «−», поле только для чтения
с количеством за выбранный день и кнопка «+». Каждое нажатие изменяет число
на один; при нуле «−» недоступен. Рядом — кнопки «Кинул» и «Накосячил»,
повторное нажатие на них снимает отметку. Для нового косяка
сначала открывается выбор причины из базы; «Сохранить» подтверждает отметку,
«Отмена» закрывает окно без изменений. Активный статус выделен
цветом и галочкой. Сам список лежит в `public/names.js`
в массиве `window.ROSTER` — это единственное место, которое нужно править:

```js
window.ROSTER = [
  "Аня",
  "Борис",
  "Вера",
];
```

Файл отдаётся как обычная статика, сервер его не читает и не проверяет.
После правки достаточно обновить страницу — перезапускать `node server.js`
не нужно.

К списку автоматически добавляются ранее отмеченные участники из базы.
Имена сортируются по алфавиту. Все участники остаются видны независимо от
отметок за выбранный день. Во время сохранения кнопки временно блокируются,
чтобы повторный клик не отправил ещё одну операцию. При ошибке статус сохраняет
предыдущее значение, а рядом появляется сообщение. На узком экране кнопки
переносятся под имя участника.

## Обязательные участники

В `public/names.js` рядом с ростером лежит `window.REQUIRED` — «отцы-кафахлёбы».
Если при увеличении посещений в дне не окажется никого из них, запрос не уходит вовсе,
а под списком участников появляется предупреждение из `window.REQUIRED_NOTE`:

```js
window.REQUIRED = ["Миша", "Кирилл"];
window.REQUIRED_NOTE = "Кафа без отцов-основателей кафахлёбства не засчитывается";
```

Достаточно одного любого из списка. Пустой массив выключает проверку.

Проверяется состав дня с учётом нового участника: если «отец» уже
отмечен в этом дне раньше, добавлять к нему остальных можно свободно — иначе
после первого сохранения день оказался бы заперт.

Имена из `REQUIRED` всегда попадают в список участников, даже если их нет в
`ROSTER`. В пустом дне сначала отметьте одного из них, затем остальных.

Предупреждение исчезает при следующем нажатии на статус или смене дня. Верхний баннер остаётся под ошибки сервера — правила учёта
и сетевые сбои не смешиваются.

Уменьшение количества посещений этим правилом не ограничивается.

Проверка живёт на клиенте: это правило учёта, а не безопасность. Прямой запрос
к API её не увидит.

## Кидки

Кидок — это когда человек обещал прийти и не пришёл. Отмечается кнопкой
«Кинул» напротив имени. Активная кнопка выделяется кирпичным цветом;
повторное нажатие снимает кидок.

Внизу страницы из кидков собирается рейтинг «кто чаще кидает» — те же полоски,
что и у «кто ходит чаще», только цветом кидков. Сверху те, за кем больше кидков:
1 антиранг у того, кто кидает чаще всех. Кто не кидал ни разу, в списке не
показывается. Карточка скрыта, пока кидков нет вовсе.

Правила:

- **Хитмап кидки не красят.** Сетка вверху по-прежнему считает только приходы,
  день с одними кидками остаётся серым.
- **Посещения и кидки независимы.** Человек мог прийти несколько раз и
  пропустить другой сбор. Кидок не обнуляет счётчик, а «+» не снимает кидок.
- **Правило «отцов» на кидки не распространяется**: кидок — не день кафы, а
  его отсутствие. Кинуть можно кем угодно и в любой день, `window.REQUIRED`
  ограничивает только добавление посещения.
- Человек остаётся в списке. Повторное нажатие «Кинул» снимает только кидок.

### Картинки антирангов

Рейтинг кидков умеет показывать картинки так же, как `RANKS` у приходов: 1 антиранг
достаётся тому, за кем кидков больше всех. За них отвечает `window.ANTIRANKS`
в `public/names.js`:

```js
window.ANTIRANKS = [
  "/antiranks/1.webp",
  "/antiranks/2.webp",
];
```

Файлы лежат в `public/antiranks/`; папка монтируется с хоста наравне с
`public/ranks/`, так что пересборка не нужна. Размер тот же, что у рангов, —
64 пикселя по высоте. Пустой список `[]` — имена и полоски без картинок.

## Косяки

Рядом с активной кнопкой «Накосячил» появляется кнопка ⓘ. Она открывает
сохранённую причину за выбранный день без изменения отметки. Если у человека
несколько косяков за день, показываются причины всех записей. Просмотр доступен
без входа. Поле API `failDetails` содержит записи по датам: `id`, `name`,
`reason_id` и текст `reason`.

Косяк — отдельная отметка, кнопка **«Накосячил»** напротив имени.
Он независим от посещений и кидков: можно прийти и всё равно накосячить,
поэтому косяк ничего не снимает и его самого ничего не снимает. Активная кнопка
выделяется жёлтым цветом; повторное нажатие снимает косяк.

Правила:

- **Хитмап косяки не красят**, как и кидки: сетка вверху считает только приходы.
- **Правило «отцов» на косяки не распространяется** — косякнуть можно в любой
  день, `window.REQUIRED` ограничивает только добавление посещения.
- Косяк можно поставить или снять независимо от посещения и кидка.
- Внизу страницы собирается рейтинг «кто чаще косячит»: сверху те, за кем
  косяков больше. Кто не косячил, в списке не показывается, карточка скрыта,
  пока косяков нет вовсе.

### Картинки за косяки

Работают как антиранги, за них отвечает `window.FAILRANKS` в `public/names.js`:

```js
window.FAILRANKS = [
  "/fails/1.webp",
  "/fails/2.webp",
];
```

Файлы кладите в `public/fails/`; папка монтируется с хоста наравне с
`public/ranks/` и `public/antiranks/`, так что пересборка не нужна. Размер тот
же — 64 пикселя по высоте. Пустой список `[]` — имена и полоски без картинок.

## API

| Метод    | Путь                                | Что делает                  |
|----------|-------------------------------------|-----------------------------|
| `GET`    | `/api/log`                          | всё состояние               |
| `POST` | `/api/days/:date/visits/increment` | увеличить посещения на 1, тело `{"name":"…"}` |
| `POST` | `/api/days/:date/visits/decrement` | уменьшить посещения на 1, тело `{"name":"…"}` |
| `POST`   | `/api/days/:date/skips`             | отметить кидок, тело такое же |
| `DELETE` | `/api/days/:date/skips/:name`       | снять кидок                 |
| `POST`   | `/api/days/:date/fails`             | отметить косяк, тело `{"name":"…","reason_id":2}` |
| `DELETE` | `/api/days/:date/fails/:name`       | снять косяк                 |

Дата — `ГГГГ-ММ-ДД`. Имена в URL нужно кодировать (`encodeURIComponent`).
Изменение счётчика выполняется в транзакции, включая параллельные запросы.
При уменьшении до нуля запись посещений удаляется; уменьшение нуля ничего
не меняет. Посещения, кидки и косяки не снимают друг друга. Старые маршруты
`attendees` удалены — фронтенд и сервер необходимо обновлять вместе.
Каждый POST принимает одного человека: `{"name":"…"}`. Поле `names`, массив
вместо объекта, пустое или некорректное имя возвращают ошибку 400.
Любой изменяющий запрос возвращает новое состояние целиком, так что клиенту
не нужен отдельный `GET` после записи.

## Хранилище

Сервер читает и изменяет `data.sqlite`; путь задаётся через `DATA_FILE`.
Используется Node.js 22.13+ и встроенный `node:sqlite`, npm-зависимостей нет.

| Таблица | Колонки |
|---------|---------|
| people | id, name |
| visits | id, date, person_id, count |
| skips | id, date, person_id |
| reasons | id, reason |
| fails | id, date, person_id, reason_id |

Сервер использует готовую схему с колонкой `visits.count` и не изменяет её
при запуске. На сервер необходимо загрузить базу, в которой эта колонка уже
существует. При отсутствии колонки запуск завершится с ошибкой.
В таблице хранятся положительные целые количества. Для человека за день
счётчик обновляется в существующей записи. Если вручную были созданы дубли,
при изменении их количества суммируются в одной записи.

API возвращает `{ days, people, skips, fails, reasons, failDetails }`.
`days` содержит массивы `{ name, count }` по датам, `skips` и `fails` — массивы
имён по датам. Хитмап, итоги дня и рейтинг посещений суммируют `count`; число
дней считается отдельно. Справочник причин `[{ id, reason }]` служит для окна выбора. Справочник редактируется
в SQLite. Новый косяк требует целочисленный `reason_id`, существующий в таблице
`reasons`; отсутствующее или неверное значение возвращает ошибку 400. Новые
причины автоматически не создаются. Существующие причины и ID записей не
перезаписываются при других отметках. Повторный POST того же человека за тот
же день сохраняет существующий косяк и его причину.
Удаление косяка через текущий API снимает все его записи для человека за день.

Каждая отметка выполняется в транзакции: ошибка откатывает изменение целиком.
Данные читаются из базы при каждом запросе, поэтому сохранённые ручные правки
видны при следующем обновлении страницы без перезапуска сервера.


## Что стоит знать

- Изменения защищены паролем, если заданы `AUTH_USER` и `AUTH_PASS`.
  Просмотр доступен без входа.
- Открытые вкладки опрашивают сервер раз в 5 секунд, поэтому чужие отметки
  подтягиваются сами. В фоне опрос не идёт, зато при возврате на вкладку данные
  обновляются сразу, не дожидаясь следующего тика.
- Цвет считается по приходам относительно максимума по всем дням, а не по
  фиксированной шкале: календарь выглядит одинаково живым и для троих, и для
  тридцати человек. Кидки на цвет не влияют.
- Сетка показывает последний 371 день и всегда заканчивается сегодняшним днём.
- Имена сравниваются без учёта регистра, пробелы схлопываются: `" аня "` и
  `"АНЯ"` — один человек.
